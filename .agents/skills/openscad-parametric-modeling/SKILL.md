# OpenSCAD Parametric Modeling Skill

**Expert in creating and modifying OpenSCAD (.scad) files for 3D-printable parts — especially adapting existing parametric models (e.g. Thingiverse/Code-and-Make designs) to fit real-world objects, and troubleshooting the export/print pipeline.**

## Core Capabilities

- Create new `.scad` files from requirements (holes, cups, holders, brackets)
- Adapt existing `.scad` designs by changing top-level parameters only
- Resize bores, magnet pockets, walls, and depths for real objects
- Diagnose STL scale/unit problems and slicer mismatches
- Verify exported STL geometry (bounding box, triangle count) via PowerShell

## Workflow

### 1. Gather real dimensions first

Before editing, confirm the actual measured size of the target object (e.g. handle diameter, magnet size). Ask the user if unknown. Never guess fit dimensions — printed parts are expensive to iterate.

### 2. Modify parameters, not geometry

Well-structured `.scad` files derive everything from top-level parameters. To resize:

- Identify the top-level parameter block (`/* [Something] */` sections in customizer-style files).
- Change ONLY the parameter values; derived variables (`baseWidth = penHoleDiameter + Material_Thickness * 2;`) update automatically.
- Common adaptations:
  - Bore/hole diameter: set to object diameter + clearance (see Fit table below).
  - Depth/height: set to object length + margin.
  - Magnet holes: set diameter/thickness to the actual magnet size (exact size = press fit; +0.2–0.3 mm = slip fit).
- Keep a comment on each changed parameter noting the real-world object it fits.

### 3. Preserve the original design intent

When a user says "make it exactly like X but with Y changed":

- Copy the source file verbatim.
- Change only the requested parameters/values.
- Rename user-facing parameter names only if it aids clarity (e.g. `Pen_Hole_Diameter` → `Frother_Hole_Diameter`) — but keep internal variable names and module structure identical so the design behavior is unchanged.
- Note the changes in a header comment.

### 4. Common geometry patterns

- **Solid cone at bore bottom**: `cylinder(d1 = 0, d2 = D, h = D)` inside a `difference()` creates a tapered solid base. To make a through-bore (object slides all the way through), replace with `translate([0, 0, -0.01]) cylinder(d = D, h = depth + 0.02)`.
- **Magnet holes from rear**: `rotate([270, 0, 0]) cylinder(d = D, h = depth + 1)` — the +1 overshoot guarantees a clean cut through the face.
- **Ridges/lips**: `rotate_extrude()` of a small circle translated to the wall mid-thickness.
- **$fn**: 100 is a good default for printed circles; use 96+ for visible round surfaces.

### 5. STL export and verification

OpenSCAD units are millimeters; STL files are unitless (1 unit = 1 mm assumed by slicers).

**Correct export procedure (always instruct the user):**
1. Open the `.scad` in the OpenSCAD desktop app.
2. Press **F6** (full render — F5 preview cannot export).
3. File → Export → Export as STL.

**Never** use online `.scad`→STL converters (e.g. ImageToStl.com) — they ignore customizer parameters and/or render at wrong scale. Header string `STL generated by ImageToStl.com` in a binary STL is the telltale sign.

**Verify an STL bounding box with PowerShell** (binary STL):

```powershell
$f = "<path-to.stl>"
$bytes = [System.IO.File]::ReadAllBytes($f)
$triCount = [System.BitConverter]::ToUInt32($bytes, 80)
$mins=@(1e9,1e9,1e9); $maxs=@(-1e9,-1e9,-1e9)
for($i=0;$i -lt $triCount;$i++){
  $off=84+50*$i
  for($v=0;$v -lt 3;$v++){ for($c=0;$c -lt 3;$c++){
    $val=[System.BitConverter]::ToSingle($bytes,$off+12+$v*12+$c*4)
    if($val -lt $mins[$c]){$mins[$c]=$val}
    if($val -gt $maxs[$c]){$maxs[$c]=$val}
  }}
}
"Triangles: $triCount"
"Size: X=$([math]::Round($maxs[0]-$mins[0],2)) Y=$([math]::Round($maxs[1]-$mins[1],2)) Z=$([math]::Round($maxs[2]-$mins[2],2)) mm"
```

Compare the result against expected dimensions (e.g. hole Ø + 2×wall thickness, depth + base thickness). A mismatch means the wrong file was exported or a converter mangled it.

### 6. Fit / clearance rules of thumb

| Fit type | Clearance (on diameter) |
|---|---|
| Snug slide fit (round bore) | +0.4–0.6 mm |
| Easy slide fit | +1.0–1.5 mm |
| Loose / user-requested "easier" | +2–3 mm |
| Magnet press fit | exact size (or +0.1 mm) |
| Magnet slip fit | +0.2–0.3 mm |

Printers with poor dimensional accuracy (e.g. first-layer elephant-foot) may need more; suggest a small single-wall test print if unsure.

## Conventions

- Version iterations as new files: `name-v2.scad`, `name-v3.scad` — never overwrite a file the user may want to compare against.
- Add a header comment block: what the part is, what it's based on, and a changelog line per version.
- Keep customizer-style `/* [Section] */` comments and `// description` + `// [min:step:max]` annotations intact so the OpenSCAD customizer still works.
- After edits, tell the user the expected printed dimensions so they can sanity-check the slicer.
